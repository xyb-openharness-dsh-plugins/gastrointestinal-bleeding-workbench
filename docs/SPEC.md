# 消化道出血工作台规格

版本：M1 草案 v0.1（需求假设；未经患者/临床签认）。G1 自动签认通过，待晨审追认。产品暂用名「消化道出血工作台」，待用户追认。

## 目标和范围

目标用户暂定中国大陆、简体中文成人患者与照护者（待用户确认）。在疑似消化道出血情境中，帮助识别需要立即求助的表现，并快速整理发生时间、用户观察事实、记录者身份及既有就诊资料。优先级为：**先求助 → 可选记录 → 事实摘要交接**。

### 非目标与安全边界

- 不诊断、不鉴别病因、不预测风险、不计算出血量、不生成分诊等级或评分。
- 不建议用药、停药、进食/禁食或其他处置；不评价院内治疗。
- 不以症状未出现、问卷完成、阴性答案或 AI 输出排除危险。
- 急诊求助出口首屏可达，且记录可整体跳过；求助不等待填写或 AI。
- 只整理用户提供事实；时间不明、来源不明和字段缺失均明确保留未知，不补全、不推测。
- 合成资料全部显著标识为模拟数据；禁止真实患者数据入仓。

## 核心场景

引用 `docs/SCENARIOS.md`：S1 突发信息不全、S2 照护者代记、S3 既往背景、S4 就诊后随访。最高优先为 S1。真实用户需求与指南/专家意见分开；本规格当前只依赖用户派单及桌面研究。

## 首版功能

1. `HELP-01`：首屏求助提示和紧急求助出口，不被任何流程、面板或弹窗遮挡。
2. `RECORD-01`：用户主动选择后记录发生时间/时间范围、观察事实、观察者/记录者、事实来源、既往背景和就诊资料名称；均可缺省或跳过。
3. `SUMMARY-01`：生成可复制或导出的时间序列事实摘要，标注记录主体、来源和未知项；不得含结论/风险/处置建议。
4. `SYNTHETIC-01`：至少四组完全合成情境，覆盖 S1–S4；无任何患者级数据。
5. `ACCESS-01`：简体中文、键盘可达、大字和窄屏下求助入口持续可见。
6. `AGENT-01`：如果确认接入 DSH 原生 Agent，仅用于按用户选定内容整理草稿；不得构造医学结论、自动发送或覆盖原生草稿。未完成目标 Desktop 合同验证前均显示未验证，不提供伪造聊天框。

## 用户流程

首屏求助出口 / 用户选择记录 / 记录事实或跳过 / 预览事实摘要 / 复制或导出 / 结束返回。任何一步均可返回首屏求助；记录中断、浏览器刷新、数据不可保存时不影响求助功能。高压情况下只允许一键求助，不要求先阅读免责声明或完成问卷。

## 来源及医学内容治理

来源清单和范围见 `docs/USER-RESEARCH.md`。ACG 2021、WSES 2020 是指定参考线索，不是全范围或唯一现行指南；2025 AWMF 综合指南、2026 ESGE 消化性溃疡出血更新与 ACG 2023 下消化道指南已检索到。中国来源中的院内诊疗内容不直接照抄。患者版仅使用经过临床审阅的识别与求助语言；临床责任人待定。

## 数据候选（不构成 schema 冻结）

稳定记录候选：subject/pseudonymous local profile、episode、observation、source attribution、document reference、revision、author/observer。工作流状态、草稿和展示摘要是可变读模型；不复制成独立事实。M2 交互确认前仅作概念，不建立生产表/迁移。真实文档默认本地、用户显式选择；不默认上传。

## UI 和原型关口

`docs/28-INTERACTION-PATH-DESIGN.md` 给出 CRUD 双通道草案。M2 HTML 原型必须能独立打开和操作；显著标识合成数据；覆盖求助/跳过、照护者身份、四类情境、键盘/窄屏和空字段。路径、原型版本/hash、实际预览与用户确认写入 `docs/PROTOTYPE-REVIEW.md`。当前尚无原型，用户尚未确认；生产实现不得先行。

## 验收标准

- A1：首屏有醒目、持续可达的紧急求助出口；不依赖记录或判断结果。
- A2：完整跳过记录可直达求助；无风险数值/分级。
- A3：记录时间、原样事实、观察者、来源、可选背景/既有资料；缺失不推断。
- A4：照护者代记与本人亲见/转述明确区分。
- A5：摘要仅包含用户输入的可追溯事实、未知项和资料清单，无诊断/处置建议。
- A6：至少四组合成资料具名标识且不含可识别真实患者数据。
- A7：窄屏/大字/键盘时求助仍可访问；错误与空态不误导。
- A8：原生 Agent 入口若存在，确认前不发送；冲突时保留原生草稿。
