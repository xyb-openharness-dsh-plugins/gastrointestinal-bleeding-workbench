# 交互路径与 CRUD 双通道（M1 草案，供 M2 原型落实）

状态：基于已知需求的路径草案；尚未用户签认。求助优先、跳过可用已由用户明确授权。

| 场景 | 首页入口 → 步骤 → 产物 → 返回首页 | AI 协助默认 | 手工通道 | 更正/删除 |
|---|---|---|---|---|
| S1 突发/信息不全 | 首屏紧急求助 / 开始记录（可选）→事实与时间（可跳过）→预览→复制/分享事实摘要→返回 | 可选帮助把用户原话整理成草稿；不能推断/分级，发送前预览确认 | 可直接输入/跳过 | 修改记录保留来源和修订；删除只删本机草稿，不能影响求助入口 |
| S2 照护者代记 | 首屏求助 / 照护者记录→记录者与患者关系→亲见/转述事实→摘要→返回 | 只做格式整理，不补事实 | 逐条手工记录 | 可更正并保留“由谁/何时修订”；删除草稿需确认 |
| S3 既往背景 | 记录页→可选添加背景/资料名称与日期→摘要→返回 | 仅提取用户选中的原文事实，需逐项确认 | 手工填写资料名称、日期或自述 | 错误项更正；原始资料引用与转录记录分别管理 |
| S4 就诊后随访 | 首屏求助 / 记录后续观察→就诊时间/资料→按时间线预览→返回 | 可整理已确认事实，不评价医疗处置 | 手工新增观察 | 保留更正历史；再次紧急求助始终优先 |

## CRUD 约束

- Create：建立一条观察/就诊事件，时间、记录主体和来源独立表达。
- Read：按时间查看，可区分本人亲见、照护者代记、既有文书摘录和未核实转述。
- Update：更正事实，不静默覆盖；记录修订者和时间。
- Delete：删除未保存草稿或用户选择的本地记录前明确说明后果；不能删除/隐藏紧急求助出口。
- AI 通道只能协助整理记录；手工通道必须同样可达。无原生 Agent 面板时不虚构 AI 接通。
